# Decisiones

Cada decisión que cambia cómo se construye o cómo se ve el sistema se anota aquí, con la fecha y el motivo. Las marcadas como **Propuesta** se confirman con el equipo (y, si afectan al usuario, con el taller) antes de implementarlas; al confirmarlas se quita la marca.

| Fecha      | Decisión                                                                                                                          | Por qué                                                                                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Semana 8   | Next.js full-stack (monolito modular) en lugar de Flask + HTML/CSS                                                                | Un solo proyecto para pantallas y API reduce la complejidad de operación                                                                                  |
| Semana 9   | Medir la desviación con ΔE (CIELAB, fórmula CIE76) en lugar de porcentaje por canal RGB                                           | ΔE es el estándar de la industria del color y da un solo número interpretable                                                                             |
| 2026-11-03 | Sin registro público: los usuarios se crean con `scripts/crear-usuario.ts`                                                        | Pocos usuarios, todos del taller; evita una pantalla de registro expuesta                                                                                 |
| 2026-11-08 | La web elige qué lote usa el sensor y en qué modo (`Inactivo`, `Muestra`, `Recoleccion`); un solo lote captura a la vez           | Hay un solo sensor; así el puente no se reinicia para cambiar de lote o de modo, y la base impide dos capturas simultáneas                                |
| 2026-11-08 | Una alerta roja pausa el lote y detiene su captura en la misma sentencia                                                          | Evita seguir registrando tarros de un lote con desviación acumulativa                                                                                     |
| 2026-11-09 | Cada módulo separa `repositorio.ts` (SQL), `reglas.ts` (puras) y `servicio.ts` (orquestación); `route.ts` solo valida y responde  | Permite probar las reglas sin base de datos y alcanzar la cobertura de ACQ-03                                                                             |
| 2026-11-10 | Tolerancia de ΔE de 0,8 a 8,0                                                                                                     | El prototipo (TCS3200 en caja oscura, cubos pintados a mano) repite entre 3 y 5,5 ΔE leyendo el mismo cubo; con 0,8 todas las lecturas salían No aprobado |
| 2026-11-13 | Estructura de `docs/` (producto, arquitectura, decisiones, diseño, specs, tareas, contratos, operación)                           | Un solo lugar para saber qué se construye, cómo y por qué, legible para el equipo y para los asistentes de IA                                             |
| 2026-11-13 | **Propuesta.** La interfaz se diseña para personas mayores de 55 años: texto base de 18 px, botones de 56 px o más, contraste 7:1 | Es el perfil de los usuarios del taller; ACQ-01 exige que el 80 % complete el flujo sin ayuda                                                             |
| 2026-11-13 | **Propuesta.** Encabezado oscuro con el logo y contenido claro (texto oscuro sobre fondo claro)                                   | El logo es claro y necesita fondo oscuro; el texto oscuro sobre fondo claro se lee mejor, y la ventaja crece con la edad (Piepenbrock et al., 2013)       |
| 2026-11-13 | **Propuesta.** Fuente Atkinson Hyperlegible Next para todo el texto                                                               | Diseñada para baja visión: distingue 1, l, I y 0, O                                                                                                       |
| 2026-11-13 | **Propuesta.** Tomar la muestra y revisar tarros se hacen en una pantalla completa; cerrarla detiene la captura                   | El usuario ve sin buscar qué está haciendo el sensor; si la pantalla completa está cerrada, el sensor no está capturando. Nunca hay una captura invisible |
| 2026-11-13 | **Propuesta.** Textos de las acciones: "Tomar muestra patrón", "Revisar tarros", "Terminar revisión"; trato de usted              | Palabras del taller en lugar de nombres del sistema ("Registrar muestra", "Iniciar recolección"); confirmar con el taller cuáles palabras usa              |
| 2026-11-13 | Un solo perfil de usuario (operador mayor de 55 años) y una sola cuenta del taller, sin roles                                     | Una sola persona toma la muestra y revisa los tarros; el inicio de sesión se mantiene por seguridad                                                       |
| 2026-11-13 | Objetivo del MVP: el dictamen coincide con el juicio visual de una persona experimentada en al menos el 90 % de los tarros        | Valida la idea central: medir el color reemplaza la comparación a ojo; la facilidad de uso es una condición, no un objetivo aparte                        |
| 2026-11-13 | Se mantiene la pausa automática por tendencia (tres lecturas crecientes y la última > 8,0)                                        | Detecta lecturas que se desvían de forma progresiva, algo que una lectura aislada no muestra; sirve a la precisión                                        |
| 2026-11-13 | Un lote pausado se reanuda desde la web: el aviso rojo se mantiene 5 s y luego aparece "Reanudar revisión"                        | Con un solo operador, sin reanudar el lote quedaría bloqueado; la espera obliga a leer el motivo antes de seguir                                          |
| 2026-11-13 | Navegación: "Lotes" es el inicio, "Historial" es un enlace secundario y la pantalla completa oculta la navegación                 | El flujo principal es abrir lote → tomar muestra patrón → revisar tarros; el historial no compite con él                                                  |
| 2026-11-13 | Las seis funcionalidades se presentan como cinco: F4 y F5 forman "Revisar tarros con dictamen y alertas"                          | Para el operador la alerta es parte del dictamen; no se elimina nada del proyecto, solo cambia cómo se ve                                                 |
